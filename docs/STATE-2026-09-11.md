# Where the pantry stands, 11 Sep 2026

Written at the end of phase 3, before phase 4 is planned. `ROADMAP-PHASE-3.md`
records what each milestone did and why. This records what is *not* in there:
what was built off the back of testing, what is known to be wrong, and what a
phase 4 would be walking into.

## Built after the roadmap was written

These came out of using the thing, not from the plan.

- **S5b, restock targets in the thing itself.** "Keep 6" on a box of six eggs
  suggested buying thirty. One column, `restock_target`, always in the item's own
  unit; packs appear only when buying, rounded up.
- **Add/edit parity.** The add form could set ten fields where the item page
  could set fourteen.
- **Substitutes.** A stand-in picker per ingredient, ranked by shared tags
  weighted by rarity, then name similarity.
- **Per-recipe cook history**, and **per-portion nutrition** on recipes.
- **Generic nutrition estimates** for things no barcode covers, with
  `nutrition_source` recording where every figure came from.
- **Expiry across containers.** Finishing a pack clears the finished packet's
  date and asks for the new one after cooking.

## Known wrong, or knowingly left

- **`items.name` uniqueness was fixed; `items.category`, `items.shop`,
  `items.restock_to` and `items.restock_min` are frozen, not dropped.** Nothing
  writes them. Dropping them needs another `rebuild-items.mjs` run, which is
  safe but has not been done because there is no reason to.
- **One pantry item has no nutrition and never will**: MSG. Nothing in the
  generics table is honest about it.
- **Recipe lines whose unit is a word the pantry does not know** drop out of
  nutrition totals. "2 cinnamon sticks" is the live example - `stick` is not a
  unit, so the line is skipped even though the item has figures and a weight.
  Fixable by teaching `pack_size`/`pack_unit` on that recipe line.
- **The receipt scanner has only been tried on one real receipt**, which worked.
  Thermal paper varies enormously and the preprocessing in `lib/scan-image.ts`
  is the first place to tune if it struggles.
- **Nutrition estimates are approximate by construction.** A large onion is
  twice a small one. They are marked `estimate` everywhere they appear so they
  are never mistaken for a measurement, and that marking is the feature.
- **The social layer has had a design pass but almost no use.** Feed, search,
  likes, comments and blocking were built quickly in phase 2 and have one
  household in them.

## Things a phase 4 would inherit

- **The old sqld token is still valid.** Phase 1's pen test flagged it: the
  pre-rotation token has no expiry and sqld has no revocation list, so killing it
  means regenerating the keypair and restarting sqld - production downtime that
  has never been taken. This is the oldest outstanding item in the project.
- **No CSP or `X-Frame-Options`** on the app, also from that pen test.
- **`db.packthings.fyi` is reachable from the open internet.** Guarded by a JWT,
  but reachable.
- **There is no test suite**, only the four check scripts. They cover the parts
  that were got wrong before, which is a deliberate but narrow choice.
- **`estimateMissing` runs on demand and on write.** Nothing sweeps
  periodically, so if the generics table grows, existing items with `NULL`
  figures only pick it up when somebody presses the button.

## Parked on purpose

`ROADMAP-PHASE-3.md` has one: **nutrition facts read off the packet by camera**.
Pinned because barcodes and the generics table between them already cover 28 of
29 items, and a curved packet in kitchen light is a harder photograph than a
receipt flat on a table.

## Shape of the data, as it now is

An item is **containers**: `sealed_count` full packs of `pack_size`, plus
`quantity` in the open one. It carries **tags** (many, one primary, per kitchen),
**shops** (many, one preferred, per kitchen), a **restock target** in its own
unit, **nutrition** with a recorded source, and the usual dates.

A recipe is a **document** - ordered steps, ordered ingredients, portable by
name rather than by stock id - with an author, a visibility, and a lineage.

Both of those shapes were arrived at by getting them wrong first, and the
reasoning is in the commit messages.
